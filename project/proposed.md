# 利他行動の進化・維持条件を調べるための改善計画

## 1. 調査結果と研究上の位置づけ

**現在の譲渡回数だけでは、利他行動が進化・維持されたとは判断できません。** 負の譲渡や処理順依存という実装上の問題に加え、死亡閾値の変更が行動入力・譲渡可能量・出生時の生存余裕を同時に変えているためです。

現行モデルは、行動決定用の重みを子に継承し、突然変異と生存・繁殖によって選択する仕組みです。個体内で学習するアルゴリズムではありません。したがって、研究では「譲渡が起きる条件」と「譲渡する遺伝的戦略が増える条件」を区別します。

確認した作業ツリーのコードを対象に分析しました。既存の未コミット変更には手を加えず、シミュレーションのコードも変更していません。以下の再現結果は、メモリ上で設定した少数個体の実験によるものです。

## 2. 実装・更新アルゴリズムの問題

| 優先度 | 問題と根拠 | 研究結果への影響 |
|---|---|---|
| 最優先 | [field.py](src/field.py) の譲渡量に下限がない。代謝後に死亡閾値を下回ると `actual_transfer` が負になる。 | 援助のつもりで相手からエネルギーを奪い、それを利他行動として数える。 |
| 最優先 | 行動は一括決定するが、譲渡・移動・採食は個体ごとに逐次適用する。 | 先に受け取ったエネルギーを同じステップで再譲渡できる。回避対象の位置も更新途中の値になる。 |
| 最優先 | 餌の配列が整数型なのに、残量と報酬は小数を許容する。 | 資源の消費と獲得が一致しない。残量未満への制限もなく、少量の餌から過大な報酬を得られる。 |
| 高 | 譲渡量がゼロでも回数を加算し、カウンタのリセットを呼び出し側に任せている。 | 実際の援助、実行意図、累積回数が混ざる。 |
| 高 | 個体の並びが維持され、子は親の直後に追加される。 | 処理順の有利・不利が系譜と結び付き、遺伝的戦略の選択と混同される。 |
| 高 | Python と NumPy の大域乱数を併用し、実験に seed の記録がない。 | 再現や並列実行間の比較が難しい。 |
| 中 | `get_nearest_*` は最近傍ではなく、周囲1マスから無作為に選ぶ。 | 実際と異なる相手選択規則として解釈されやすい。 |
| 中 | 閾値、確率、重みの形状などを検証していない。 | 同一の出生・死亡閾値によるゼロ除算や、不正な設定を検出できない。 |

再現できた具体例：

- 初期エネルギーが `-49.95`、死亡閾値が `-50`、代謝が `0.1` の個体は、`-0.05` を「譲渡」し、相手のエネルギーを減らしました。回数は1増えます。
- 同じ2個体で処理順だけを逆転させると、ステップ終了時の生存数が2体から1体に変わりました。
- 餌残量5、報酬 `0.5` では、獲得量は `0.5` なのに残量は4になりました。餌の初期残量 `0.5` は整数化され、ゼロになります。

また、[simu_every_para.py](scripts/simu_every_para.py) は廃止された `transfer_amount` 引数を渡しており、現行の `Field` では実行できません。多数派判定の分母も出生・死亡後の個体数なので、行動した集団と一致していません。

## 3. モデル・測定上の問題

**死亡閾値の掃引は、飢餓耐性だけの実験になっていません。**

[agent.py](src/agent.py) の正規化には死亡閾値が入るため、同じエネルギー・同じ遺伝子でも閾値を変えると行動が変わります。譲渡上限も `energy - death_threshold` に依存します。

さらに、生存余裕を \(R=E-D\)、死亡閾値を \(D=-S\) とすると、エネルギー0で生まれる子は \(S\) の余裕を持ちます。出生閾値 \(T\) ちょうどで親子のエネルギーを0にする場合、出生前後の総余裕の差は、

\[
\Delta R=2S-(T+S)=S-T
\]

です。`T=100` の場合、死亡閾値 `-50` では余裕が50減り、`-300` では200増えます。これは生存余裕を資源として解釈した場合の収支であり、**死亡閾値によって繁殖の実質的なコストまで変わる**ことを示します。

そのほかの重要な制約は次のとおりです。

- **譲渡はエネルギーの再分配である。** 集団の総量は増えません。ただし、死亡回避や繁殖閾値による非線形な効果はあり得ます。瞬間的な支出だけでなく、生存・繁殖への影響を測る必要があります。
- **初期状態から譲渡戦略が存在する。** ランダムな重みから譲渡は起こり得るため、初期の行動を「進化による出現」と呼べません。
- **行動表現に制約がある。** バイアスや記憶を持たない線形入力とシグモイドなので、表現できる状況依存戦略は限られます。ゼロ重みでも判定が `>= 0.5` のため、静止・譲渡・最大量の半分という行動になります。
- **周辺個体がいない場合の入力が不自然である。** `other_energy=0` を正規化すると、他者不在でもエネルギー入力はゼロになりません。また、正規化値が常に0〜1に収まる保証もありません。
- **移動戦略と譲渡戦略の効果が混ざる。** 接触頻度や餌への接近が同時に進化するため、譲渡回数の増加だけでは譲渡戦略への選択を特定できません。
- **親子の同位置出生が局所的な系譜集中を作る。** 空間構造は進化機構の候補ですが、系譜と空間の記録がないため検証できません。空間的な移動・援助・競争の尺度を分けて調べる重要性は、[Hermsen（2022）](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1010612) でも示されています。
- **1条件1試行では確率変動を評価できない。** 長い時系列の各ステップを独立した反復として扱うこともできません。絶滅した試行を含め、試行単位で比較します。

## 4. 改善の実装計画

### 第1段階：同期更新と資源収支を正す

行動表現と出生規則はこの段階では維持し、変更の影響を分けます。

- 更新順を **開始時状態の保存 → 代謝・即時死亡判定 → 生存個体の観測・行動決定 → 譲渡の同時適用 → 移動の同時適用 → 採食 → 餌の補充 → 死亡・出生** に固定する。
- 観測対象の位置・エネルギーはステップ開始時のコピーを使う。代謝後に死亡閾値以下となった個体は、その場で死亡と判定し、行動・譲渡の受領・採食の対象から除外する。
- 譲渡直後に死亡閾値以下となった個体も即時に除外する。その個体は移動・採食を行わず、後続個体の譲渡先・回避対象にもならない。
- 譲渡量を `max(0, min(要求量, 代謝後エネルギー − 死亡閾値))` とする。同じステップの受領分は再譲渡できない。増減を集計して一括適用する。
- 餌を浮動小数点で保持し、採食量は `min(reward_food, 残量)` とする。同一マスの競合は、個体ID順に並べた候補を無作為に並べ替えて配分する。
- 餌の再発生は現行の「残量を所定値へ補充」を維持し、実際に追加した資源量を記録する。
- 乱数を `Field` が所有する `numpy.random.Generator` に統一する。初期化・突然変異・相手選択にも渡し、安定した個体ID順で抽選する。
- 不正な確率・負の資源量・不適切な閾値・非有限値・重み形状を初期化時に拒否する。

### 第2段階：測定と実験インターフェースを整える

- `Field` に `seed`、`Agent` に個体ID・親ID・出生ステップを追加する。
- `Field.step()` は、そのステップの統計を返す。開始時個体数、接触可能個体数、譲渡可能個体数、正の譲渡件数・総量、出生・死亡数、資源収支を含める。
- 主指標は「正の譲渡件数／譲渡可能個体数」と「個体・時間当たり譲渡量」。分母ゼロは欠測として保持し、絶滅とは分ける。多数派回数は補助指標にする。
- 同じ観測入力を与える評価用ケースを固定し、各遺伝子の譲渡傾向を定期測定する。ケースは餌・他者の有無、自身・他者の正規化エネルギー `0.1, 0.5, 0.9` の組合せとする。
- `transfer_amount` を `max_transfer` に統一し、実験・解析の列名も更新する。seed、全設定、モデル版、コードの版と作業ツリー差分を結果に保存する。旧CSVは別版として保持する。

### 第3段階：モデルの仮定を分離して比較する

以下を一度に変更せず、段階ごとのモデル版として比較します。

- **入力尺度の対照：** 現行の閾値依存入力と、固定尺度 `(E + 50) / 150` を比較する。固定尺度ではクリップせず、他者不在時のエネルギー入力をゼロにする。
- **出生収支の対照：** 生存余裕 \(R\) を明示し、子の初期余裕50を親が負担し、繁殖でさらに50を消費するモデルを用意する。出生可能条件は `R >= 150`、親から100を引き、子に50を与え、余剰を保持する。
- この収支モデルでは、出生時余裕・出生条件・繁殖コストを独立した設定として記録する。死亡閾値の掃引結果は、分離が確認できるまでは「生活史全体の変更」と解釈する。
- 移動を固定した対照と、移動も進化する現行方式を比較する。バイアス追加などの行動表現の拡張は、この比較後の別モデル版とする。

## 5. 検証・実験と採用基準

### 実装の検証

- 死亡閾値前後で譲渡量が負にならず、ゼロ譲渡が件数に入らない。
- 譲渡だけなら総エネルギーが保存され、循環譲渡でも同一ステップの再譲渡が起きない。
- 同じID・seedの状態では、個体リストを逆転しても結果が一致する。
- 小数の餌、残量不足、複数個体の競合で、消費資源と獲得量が一致する。
- トーラス境界、個体不在、絶滅、出生直前・死亡直前のケースを確認する。
- 同一設定・seedの再実行と、逐次・並列実行で同じ結果を得る。
- 出生収支モデルで、出生1回の総余裕の減少が繁殖消費50と一致する。

### 研究実験

- まず死亡閾値 `[-200, -150, -100, -50, -10]`、最大譲渡量 `[0, 0.5, 1, 5, 10]` を比較する。他の値は現行既定値を使う。
- 各条件は独立30試行、100,000ステップ、最後の10,000ステップを主要評価区間とする。絶滅時刻を記録し、主要区間以前の絶滅も除外しない。
- 各試行について、初期と後期の評価用譲渡傾向、譲渡量、生存率、繁殖実績、系譜の増減を比較する。信頼区間は試行単位で算出する。
- 譲渡無効の対照、固定した移動戦略の対照、各ステップ開始時に位置を無作為化する空間対照を置く。
- 全重みゼロから始めず、譲渡出力だけを常に負にした集団からの出現実験を別に行う。さらに譲渡する戦略としない戦略を5%対95%で導入する双方向の侵入実験では、移動を共通にし、突然変異を止める。
- 主要な差が見られた条件は、フィールドサイズ10・20・40、初期密度0.2で再検証する。大規模実験前に、セル単位の近傍索引で探索を高速化し、修正済み基準実装との一致を確認する。

成功基準は、**正の譲渡が正しく測定できることに加え、譲渡戦略の世代を通じた増加・維持を、初期混在、接触頻度、処理順、出生時の資源供給から区別して示せること**です。増加や維持が確認できない結果も、研究結果として扱います。
